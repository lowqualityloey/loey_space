# Session Handoff

This file is yours. It is git-ignored and never published.

It answers one question for the next session: **what is in flight, and what is the very
next move?** It is not a diary and not a memory file. When work finishes, it leaves this
file — the outcome belongs in a daily note, and anything durable belongs in `memory.md`.

Two heading names below are load-bearing: the vault's `Home.md` dashboard links
`## 🎯 Current Main Objectives` and `## 📋 Today's Immediate Next Actions` directly, so
renaming either breaks the dashboard panel even though nothing errors. A third,
`### Latest Updates`, is the heading the logging policy appends to — keep it as a level-3
heading under the session log, where the writer expects to find it.

## 🎯 Current Main Objectives

What is actively being worked on right now. One line per objective, with what "done"
means. Three is a lot; more than three usually means none of them are.

- `<objective>` — done when `<the observable condition that ends it>`
- `<objective>` — done when `<condition>`

## 📋 Today's Immediate Next Actions

The next concrete moves, in order. Each one should be small enough to start immediately
without deciding anything first.

- [ ] `<next action>`
- [ ] `<next action>`

## Blocked

Things waiting on someone or something else. Include what would unblock them, so the next
session can tell the difference between a blocker and a preference.

- `<blocked item>` — waiting on `<person, decision, or event>`

## Context worth not relearning

Anything about the current work that took effort to establish. Keep it to facts that are
not recorded in the repository itself.

- `<fact>`

## Session Log

One line per session or milestone. Newest first. This section is append-only; the sections
above are the current state and should be rewritten freely.

### Latest Updates

- [x] **[YYYY-MM-DD HH:MM]** <what changed, and what it means for the next move>
